# 2026-05-07 Update

## What changed today

Today the project moved from validated prototype into live outreach mode.

Main outcomes:

- peer and mentor validation confirmed the direction is worth continuing
- GitHub outreach was enabled for high-score GitHub leads
- send logic remained capped and threshold-based to avoid broad spam
- GitHub comment formatting was updated so outreach can mention the repo owner directly as `@username`
- a fresh scan / score / enrich cycle was run on a new batch

## Live outreach status

Live GitHub outreach is now enabled through the alternate GitHub account.

Current guardrails:

- `ENABLE_GITHUB_OUTREACH=true`
- `LIVE_SEND_LIMIT=3`
- `LIVE_SEND_MIN_SCORE=8`
- `DRAFT_LIMIT=5`

## Observed result

The first live phase proved the mechanics:

- one GitHub comment was successfully posted
- several other high-score repos were skipped because they had no open issue/discussion target

This is important because it shows the pipeline can act live, but the current target-selection rule is still conservative.

## Owner-mention update

The draft layer was updated so GitHub messages explicitly start with `@repo-owner`.

This is meant to improve the chance that the maintainer sees the message and receives a notification.

## Current constraint

The system still only comments when it finds a valid open issue target.

So live-send failure usually means:

- no open issue exists
- only pull requests are open
- the current repo is not a safe GitHub comment target

## Recommended next improvements

1. improve target selection beyond "first open issue"
2. clean up outreach copy quality further
3. add a better public-action strategy for repos with no issue target
4. automate scheduled runs with GitHub Actions
